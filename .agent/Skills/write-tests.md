# スキル: テストの追加

## 使い方
`{{placeholder}}` を埋めてAIへのプロンプトとして使ってください。

---

## プロンプトテンプレート

```
# テスト追加: {{テスト対象}}

## テスト種別
{{ユニットテスト / 統合テスト / E2Eテスト}}

## テスト対象ファイル
{{テスト対象のソースファイルパス}}

## テストファイルの配置場所
{{tests/unit/... または tests/integration/... または tests/e2e/...}}

## テストするべき関数・コンポーネント
```typescript
{{テスト対象の関数シグネチャや概要}}
```

## テストケースの要件
- [ ] 正常系: {{正常入力でのテスト内容}}
- [ ] 異常系: {{エラー・境界値のテスト内容}}
- [ ] 境界値: {{境界値テストの内容}}

## モック方針
{{
  - 外部APIは vi.mock でモックする
  - electron-store はモック不要（ユニットテストでは直接テスト）
  - Electron APIは必要に応じてvi.mockでモック
}}

## テストフレームワーク
- ユニット/統合テスト: Vitest
- E2E: Playwright (Electron対応版)

## 要件
- [ ] テストファイル名は {{テスト対象ファイル名}}.test.ts
- [ ] describeブロックにテスト対象の説明を付ける
- [ ] 日本語でテスト名を書いてよい（it('正常なエリアコードで天気データを取得できる')）
- [ ] 全てのテストが独立して実行できるよう beforeEach でリセット

## 参照ファイル
- .agent/AGENT.md（コーディング規約）
- .agent/MemoryBank/jma-api-notes.md（JMA APIのレスポンス例）
```

## ユニットテスト記入例

```
# テスト追加: weatherCodeMap

## テスト種別
ユニットテスト

## テスト対象ファイル
src/renderer/lib/weatherCodeMap.ts

## テストファイルの配置場所
tests/unit/weatherCodeMap.test.ts

## テストするべき関数
getWeatherInfo(code: string): { label: string; iconName: string }

## テストケースの要件
- 正常系: 有効な天気コード（"100", "200", "300", "400"）で正しいlabel/iconNameを返す
- 異常系: 未知のコードで "不明" または デフォルト値を返す
- 境界値: 天気コードの範囲端（"100", "413"）

## モック方針
なし（純粋関数なのでモック不要）
```
